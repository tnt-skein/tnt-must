# tnt-must

Проверки аргументов для Tarantool: неправильный аргумент роняет вызов
на месте, а отказ называет аргумент по имени и указывает на строку
вызывающего.

```lua
local must = require('tnt.must')

function M.configure(opts)
    must.table(opts, 'настройки')
    must.not_empty(opts.tag, 'метка журнала')
    must.optional.integer(opts.limit, 'предел записей')
    must.one_of(opts.level, 'уровень', { 'debug', 'info', 'error' })
    must.all.string(opts.hosts, 'адреса')
end
```

```
app/journal.lua:41: метка журнала — непустая строка, а не пустая
```

Зависимостей нет: только то, что встроено в Tarantool.

## Зачем

Число вместо строки в аргументе — ошибка программиста, и её надо показать
сразу, там, где ошиблись, а не тремя вызовами глубже с невнятным «attempt to
index a nil value». Пакет делает для этого три вещи:

- **Называет аргумент.** «метка журнала — строка, а не число» говорит, что
  чинить; «строка, а не число» не говорит ничего, когда аргументов пять.
- **Показывает значение, а не только тип.** «предел — целое число, а не 1.5»,
  «счётчик — целое uint64, а не -1LL».
- **Указывает на вызывающего.** Место в сообщении — строка, где стоит
  проверка, а не внутренности пакета. Помощник вокруг проверки переводит вину
  на своего вызывающего через `must.at(2)`.

И один общий пакет вместо проверки в каждом модуле: с гейтом «100 % убитых
мутантов» каждая проверка требует трёх тестов — на правильный аргумент,
на неправильный и на текст отказа. Здесь `must.string` проверен однажды,
и тексты отказов во всём приложении звучат одинаково.

```sh
tt rocks install tnt-must --server=https://tnt-skein.github.io/rocks

cd tnt-must && tt rocks make
```

## Как пользоваться

Проверка возвращает само значение, поэтому её пишут и присваиванием:

```lua
local tag = must.not_empty(opts.tag, 'метка журнала')
```

### Что умеет

| Группа | Проверки |
|---|---|
| Тип | `string`, `number`, `integer`, `boolean`, `table`, `callable`, `array` |
| Тип Tarantool | `uint64`, `int64`, `decimal`, `uuid`, `tuple`, `datetime`, `interval`, `error` |
| Тип по имени | `instance_of`, `kind` |
| Числа | `positive`, `non_negative`, `greater_than`, `less_than`, `between` |
| Строки | `not_empty`, `matches`, `length` |
| Перечисление | `one_of` |
| Списки | `array_of`, `all.*` |
| Таблица настроек | `options` |
| Необязательное | `optional.*` |
| Уровень вины | `at(level).*` |
| Текст без броска | `explain.kind`, `explain.array_of`, `explain.options` |

```lua
must.integer(1.5, 'предел')                     --> предел — целое число, а не 1.5
must.positive(0, 'размер куска')                --> размер куска — число больше 0, а не 0
must.between(42, 'вес', 1, 10)                  --> вес — число от 1 до 10, а не 42
must.length('Узел', 'имя', 5, 64)               --> имя — строка длиной от 5 до 64 знаков, а не 4
must.matches('узел 1', 'имя', '^[%w-]+$')       --> имя — строка по образцу ^[%w-]+$, а не «узел 1»
must.callable('print', 'обработчик')            --> обработчик — функция или вызываемая таблица, а не строка
must.array({ name = 'storage' }, 'узлы')        --> узлы — массив, а не таблица с ключом «name»
must.array_of({ 1, 'a' }, 'веса', 'number')     --> веса[2] — число, а не строка
```

`optional.*` пропускает `nil`, а всё остальное проверяет как обычно. `all.*`
проходит по списку и называет элемент местом в нём: `адреса[2]`.

### Типы Tarantool

Счётчик из `box.info`, сумма `decimal`, `uuid`, кортеж и `datetime` для
`type` — один тип, `cdata`. Пакет различает их и в отказе показывает само
значение:

```lua
must.uint64(box.info.lsn, 'lsn')               -- число Lua либо cdata: годится и то и другое
must.uint64(-1LL, 'счётчик')                    --> счётчик — целое uint64, а не -1LL
must.decimal(1.5, 'сумма')                      --> сумма — decimal, а не число
must.uuid(uuid.str(), 'идентификатор')          --> идентификатор — UUID, а не строка
must.tuple({ 1 }, 'запись')                     --> запись — кортеж, а не таблица
```

### Объединение типов и необязательные аргументы

Типы объединяются через `|`, `?` впереди разрешает аргументу не приходить:

```lua
must.kind(id, 'идентификатор', 'uuid|string')
must.kind(true, 'вес', 'number|string')         --> вес — число или строка, а не true
must.kind(nil, 'предел', '?integer')             -- то же, что must.optional.integer
```

Объект, чья метатаблица объявляет `__type`, узнаётся по имени:

```lua
local connection = setmetatable({}, { __type = 'Connection' })

must.instance_of(connection, 'соединение', 'Connection')
must.instance_of({}, 'соединение', 'Connection')    --> соединение — Connection, а не таблица
```

### Таблица настроек: `options`

Одно описание на таблицу: ключ — запись проверки либо таблица с именем
проверки и её аргументами. Незнакомый ключ — отказ: настройка с опечаткой
иначе просто не применилась бы.

```lua
must.options(opts, 'настройки', {
    tag = 'not_empty',
    limit = '?integer',
    level = { 'one_of', { 'debug', 'info', 'error' } },
    hosts = { 'array_of', 'string' },
    tls = { '?options', { cert = 'string', key = 'string' } },
})

--> настройки: ключа «limt» нет, есть hosts, level, limit, tag, tls
--> настройки.level — одно из «debug», «info», «error», а не «warn»
--> настройки.hosts[2] — строка, а не число
--> настройки.tls.key — строка, а не nil
```

Ключи в отказе идут по алфавиту: сообщение одно и то же от запуска к запуску.
`options` только проверяет — умолчаний не подставляет и таблицу не собирает.

### Уровень вины: `must.at(level)`

Помощник вокруг проверки виноват не сам — чинить надо строку, где его
позвали. Уровень считается как у `error`: 1 — строка с проверкой, 2 —
вызывающий той функции, где она стоит.

```lua
local function need_tag(opts)
    local tag = must.at(2).not_empty(opts.tag, 'метка журнала')

    return tag
end

function M.configure(opts)
    need_tag(opts)  -- отказ показывает сюда, а не внутрь need_tag
end
```

> **Осторожно.** Хвостовой вызов `return must.x(...)` снимает кадр функции
> со стека, и вина уходит на кадр дальше. Проверка, которая должна показывать
> на свою строку, ставится отдельным предложением или в скобках:
> `return (must.x(...))`.

### Бросок без места и текст без броска

Не всякому отказу нужно место: текст, который уходит оператору или сверяется
целиком, приписка «файл:строка:» только портит. Для этого есть `fail.raise` —
бросает значение как есть, — и `must.explain`, который возвращает текст отказа
либо `nil` и ничего не бросает:

```lua
local explain = require('tnt.must').explain
local fail = require('tnt.must.fail').raise

local complaint = explain.options({ buid = 1 }, 'приложение', { build = '?', name = '?' })
--> приложение: ключа «buid» нет, есть build, name

if complaint ~= nil then
    fail(complaint)
end
```

## Как устроено

Сами проверки ничего не бросают — они возвращают текст отказа либо `nil`.
Бросает один переходник, и `error(message, level)` стоит в нём в единственном
экземпляре: иначе у составных проверок вроде `optional.string` место
в сообщении съезжало бы внутрь пакета на кадр. Это закреплено тестом, который
зовёт проверку из чанка с выдуманным именем файла и требует в отказе именно
его.

Реестр проверок один: по нему собирается фасад, из него же проверка берётся
по имени в `kind`, `array_of` и `options`, и он же перечисляет известные
проверки в отказе об опечатке.

## Проверки

```sh
make deps          # luatest, luacheck и luacov в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (296 мутантов в восьми
модулях). Проверки типов Tarantool идут живьём на узле 3.8; отказы
сверяются текстом целиком, включая место.
