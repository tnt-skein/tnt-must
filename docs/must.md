# Проверки аргументов

`tnt-must` проверяет **аргументы функций** и **бросает** на неправильном:
число вместо строки — ошибка программиста, её надо показать сразу и там,
где ошиблись, а вернуть отказ некому — тот, кто передал не то, ничего
с ним не сделает.

```lua
local must = require('tnt.must')

must.string(tag, 'метка журнала')
--> метка журнала — строка, а не число
```

Отказ называет аргумент по имени, показывает само значение и указывает
на строку вызывающего, а не на внутренности пакета.

## Зачем пакет

Проверка аргумента — одна строка, а честных тестов к ней три: на правильный
аргумент, на неправильный и на текст отказа. Три теста ради строки пишут
неохотно, поэтому проверку чаще не пишут вовсе — и функция падает позже
и не там, где ошиблись. Общий пакет переносит эти тесты в одно место:
`must.string` проверен однажды, и каждая проверка в приложении стоит ровно
одну строку.

Второе, что он даёт, — один лад отказов. Без общего пакета каждая функция
жалуется по-своему: «метка — строка, а не %s», «нужна строка, а не %s»,
«получено %s», — и по журналу не понять, что это одно и то же.

Зависимостей у пакета нет: только то, что встроено в Tarantool, — `utf8`,
`string`, `table`, `math`, а для типов Tarantool `ffi`, `decimal`, `uuid`,
`datetime` и `box.tuple`. Настроек тоже нет, поэтому нет ни `configure`,
ни `new`, ни `default`, ни `status`.

## Как пользоваться

```lua
local must = require('tnt.must')

function M.configure(opts)
    must.table(opts, 'настройки')
    must.not_empty(opts.tag, 'метка журнала')
    must.optional.integer(opts.limit, 'предел записей')
    must.one_of(opts.level, 'уровень', { 'debug', 'info', 'error' })
    must.all.string(opts.hosts, 'адреса')
end
```

Переменную зовут `must`: имя читается в месте вызова — `must.string(...)`,
`must.optional.integer(...)`. Проверка возвращает само значение, поэтому её
пишут и присваиванием:

```lua
local tag = must.not_empty(opts.tag, 'метка журнала')
```

Отказы этого набора выглядят так:

```lua
must.table('журнал', 'настройки')
--> настройки — таблица, а не строка
must.not_empty('', 'метка журнала')
--> метка журнала — непустая строка, а не пустая
must.optional.integer(1.5, 'предел записей')
--> предел записей — целое число, а не 1.5
must.one_of('warn', 'уровень', { 'debug', 'info', 'error' })
--> уровень — одно из «debug», «info», «error», а не «warn»
must.all.string({ 'storage-001', 2 }, 'адреса')
--> адреса[2] — строка, а не число
```

Имя аргумента — не украшение. «строка, а не число» бесполезно, когда аргументов
пять; «метка журнала — строка, а не число» говорит, что чинить. Имя
необязательно, но безымянный аргумент зовётся «значение», и это ровно то
бесполезное сообщение.

### Что умеет

| Группа | Проверки |
|---|---|
| Тип | `string`, `number`, `integer`, `boolean`, `table`, `callable`, `array` |
| Тип Tarantool | `uint64`, `int64`, `decimal`, `uuid`, `tuple`, `datetime`, `interval`, `error` |
| Тип по имени | `instance_of`, `kind` |
| Числа | `positive`, `non_negative`, `greater_than`, `less_than`, `between` |
| Строки | `not_empty`, `matches`, `length` |
| Перечисление | `one_of` |
| Списки | `array_of`, `all.*` |
| Таблица настроек | `options` |
| Необязательное | `optional.*` |
| Уровень вины | `at(level).*` |
| Текст без броска | `explain.kind`, `explain.array_of`, `explain.options` |

```lua
must.integer(1.5, 'предел')                     --> предел — целое число, а не 1.5
must.positive(0, 'размер куска')                --> размер куска — число больше 0, а не 0
must.between(42, 'вес', 1, 10)                  --> вес — число от 1 до 10, а не 42
must.length('Узел', 'имя', 5, 64)               --> имя — строка длиной от 5 до 64 знаков, а не 4
must.matches('узел 1', 'имя', '^[%w-]+$')       --> имя — строка по образцу ^[%w-]+$, а не «узел 1»
must.callable('print', 'обработчик')            --> обработчик — функция или вызываемая таблица, а не строка
must.array({ name = 'storage' }, 'узлы')        --> узлы — массив, а не таблица с ключом «name»
must.array_of({ 1, 'a' }, 'веса', 'number')     --> веса[2] — число, а не строка
```

`optional.*` пропускает `nil`, а всё остальное проверяет как обычно:
иначе необязательный аргумент обкладывают условием в вызывающем, и это
условие однажды пишут наоборот. `all.*` проходит по списку и называет
элемент местом в нём: `адреса[2]`. `array_of` — то же самое, но тип
элементов назван именем проверки, и потому выбирается на ходу:

```lua
must.array_of(weights, 'веса', 'between', 1, 10)
must.all.between(weights, 'веса', 1, 10)          -- то же самое
```

Опечатка в имени типа отвечает списком известных:

```lua
must.array_of({ 1 }, 'веса', 'namber')
--> веса: проверки «namber» нет, есть string, number, integer, …
```

### Типы Tarantool: `uint64`, `decimal`, `uuid`, `tuple`, `datetime`

Счётчик из `box.info`, сумма `decimal`, `uuid.new()`, кортеж, отметка
`datetime` — всё это для `type` один тип, `cdata`, и `must.integer`
отвергает счётчик с тем же «а не cdata», что и кортеж. Узнаёт тип готовая
функция Tarantool: `decimal.is_decimal`, `uuid.is_uuid`, `box.tuple.is`,
`datetime.is_datetime`, `datetime.interval.is_interval`, `box.error.is`;
целые различаются через `ffi.istype`.

```lua
must.uint64(box.info.lsn, 'lsn')               -- число Lua либо cdata: годится и то и другое
must.uint64(-1LL, 'счётчик')                    --> счётчик — целое uint64, а не -1LL
must.int64(9223372036854775808ULL, 'сдвиг')     --> сдвиг — целое int64, а не 9223372036854775808ULL
must.decimal(1.5, 'сумма')                      --> сумма — decimal, а не число
must.uuid(uuid.str(), 'идентификатор')          --> идентификатор — UUID, а не строка
must.tuple({ 1 }, 'запись')                     --> запись — кортеж, а не таблица
must.datetime(interval, 'отметка')              --> отметка — datetime, а не +1 seconds
must.error('нет связи', 'причина')              --> причина — ошибка box.error, а не строка
```

`uint64` и `int64` берут и число Lua: счётчик из msgpack приходит числом,
пока умещается в 2^53, и cdata — когда перестаёт, так что один столбец
спейса даёт то и другое. Число годится, пока оно целое и по модулю меньше
2^53: дальше double уже не хранит целые подряд, и число, прошедшее проверку,
могло бы оказаться не тем, которое записали. `uint64` пропускает
`int64_t` не меньше нуля, `int64` — `uint64_t` меньше 2^63.

Когда тип подошёл, а само значение — нет, отказ показывает значение, а не
тип: «а не -1LL», «а не 1.5» говорят, что перепутали, а «а не cdata» — нет.
`box.NULL` — cdata, равный `nil`, так приходит `null` из JSON и msgpack, —
назван по имени: «идентификатор — UUID, а не box.NULL».

### Тип по имени: `instance_of` и объединение через `|`

Объект, чья метатаблица объявляет `__type`, узнаётся по этому имени:

```lua
local connection = setmetatable({}, { __type = 'Connection' })

must.instance_of(connection, 'соединение', 'Connection')
must.instance_of({}, 'соединение', 'Connection')    --> соединение — Connection, а не таблица
must.instance_of(pool, 'соединение', 'Connection')  --> соединение — Connection, а не Pool
```

Это не наследование: сравнивается ровно одно поле, и объект с `__type =
'Pool'` за `Connection` не сойдёт — в отказе тогда его собственное имя типа.

Типы объединяются через `|`, а `?` впереди разрешает аргументу не приходить:

```lua
must.kind(id, 'идентификатор', 'uuid|string')
must.kind(true, 'вес', 'number|string')         --> вес — число или строка, а не true
must.kind(1.5, 'счётчик', 'uint64|decimal')      --> счётчик — целое uint64 или decimal, а не 1.5
must.array_of(list, 'веса', 'number|string')
must.kind(nil, 'предел', '?integer')             -- то же, что must.optional.integer
must.kind(box.NULL, 'что угодно', '?')          -- `?` сам по себе: годится всё, и nil тоже
```

Объединяются только типы — то, у чего ожидание не зависит от аргументов:
«число или строка» складывается из подписей типов, а у `between` ожидание
зависит от границ, и складывать его не из чего. `'number|between'` — отказ
на строке с проверкой: «в объединении «number|between» «between» — не тип,
типы: string, number, …». Отказ объединения показывает само значение, а не
тип: «целое число или строка, а не 1.5» говорит, чем не подошло число,
а «а не число» рядом с «целое число» сбивало бы с толку.

### Таблица настроек: `options`

Настройки описываются одной таблицей: ключ — запись проверки, как в
`array_of`, либо таблица с именем проверки и её аргументами. Незнакомый ключ —
отказ: настройка с опечаткой в имени иначе просто не применилась бы.

```lua
must.options(opts, 'настройки', {
    tag = 'not_empty',
    limit = '?integer',
    level = { 'one_of', { 'debug', 'info', 'error' } },
    hosts = { 'array_of', 'string' },
    tls = { '?options', { cert = 'string', key = 'string' } },
})

--> настройки: ключа «limt» нет, есть hosts, level, limit, tag, tls
--> настройки.limit — целое число, а не строка
--> настройки.level — одно из «debug», «info», «error», а не «warn»
--> настройки.hosts[2] — строка, а не число
--> настройки.tls.key — строка, а не nil
--> настройки.tls: ключа «ca» нет, есть cert, key
```

Ключ без `?` обязателен: «настройки.tag — непустая строка, а не nil».
Незнакомый ключ называется раньше неправильного значения, и ключи идут
в алфавитном порядке — сообщение одно и то же от запуска к запуску, хотя
`pairs` их перебирает как придётся. Вложенные настройки описываются
на месте через `{ 'options', { … } }`: реестр проверок читается при вызове,
и `options` видит в нём себя.

Ключ, значение которого вызывающий проверяет сам, описывается одиночным
`?` — «любое значение». Так удобно там, где отказы о значениях уже сложились
и сверяются целиком, а от `options` нужны только набор ключей и отказ
о чужом ключе:

```lua
must.options({ buid = 1 }, 'приложение', { build = '?', name = '?string' })
--> приложение: ключа «buid» нет, есть build, name
```

`options` только проверяет — умолчаний не подставляет и таблицу не
собирает: это дело вызывающего, и у него умолчания разных слоёв разные.

## Сообщение указывает на вызывающего

Это главное решение пакета. `error(message, 2)` ставит в начало сообщения
строку **вызывающего**, а не строку внутри `tnt-must`:

```
app/journal.lua:41: настройки — таблица, а не строка
```

Без этого человек открывает `tnt/must/fail.lua`, видит там `error(...)`
и идёт искать ошибку в чужом пакете — то есть от проверки становится хуже,
чем без неё.

Держится это так: сами проверки **ничего не бросают**, они возвращают текст
отказа либо `nil`. Бросает один общий переходник `fail.raising`, и `error(…,
level)` стоит в нём в единственном экземпляре. Иначе глубина поехала бы у тех
проверок, что собраны из других: `optional.string` — это проверка, обёрнутая
проверкой, и брось она сама, место в сообщении съехало бы внутрь пакета ровно
на один кадр. Закреплено это тестом, который зовёт проверку из чанка
с выдуманным именем файла и требует в отказе именно его.

### Уровень вины: `must.at(level)`

Помощник вокруг проверки виноват не сам — чинить надо строку, где его
позвали. Уровень считается **как у `error`**: 1 — строка с проверкой (то
же, что `must` без `at`), 2 — вызывающий той функции, где она стоит:

```lua
local function need_tag(opts)
    local tag = must.at(2).not_empty(opts.tag, 'метка журнала')

    return tag
end

function M.configure(opts)
    need_tag(opts)  -- отказ показывает сюда, а не внутрь need_tag
end
```

У набора с уровнем те же три вида: `must.at(2).optional.integer(...)`,
`must.at(2).all.string(...)`. Набор для уровня собирается один раз, и
`must.at(2)` в помощнике на каждом вызове ничего не стоит. Неправильный уровень —
не число, дробь, ноль — отказ на строке с `must.at`:

```lua
must.at(0)    --> уровень вины — число больше 0, а не 0
must.at('2')  --> уровень вины — целое число, а не строка
```

Уровень глубже стека оставляет сообщение без места — как `error`.

### Хвостовой вызов уводит место

Проверено на Tarantool 3.8: LuaJIT **снимает кадр хвостового вызова со стека
целиком**, и следа от него не остаётся даже в `debug.getinfo`. Поэтому
`return must.x(...)` и `local v = must.x(...)` показывают на разные строки:

```lua
local function tag_of(opts)
    return must.not_empty(opts.tag, 'метка')    -- кадра tag_of уже нет:
end                                              -- вина у того, кто позвал tag_of

local function tag_of(opts)
    local tag = must.not_empty(opts.tag, 'метка')  -- вина здесь
    return tag
end

local function tag_of(opts)
    return (must.not_empty(opts.tag, 'метка'))     -- скобки снимают хвост: вина здесь
end
```

Уровень тут бессилен: кадра нет, и `must.at(…)` его не вернёт ни при каком
числе — а в помощнике с `must.at(2)` хвостовой вызов сдвинул бы вину ещё на
кадр дальше. Проверка, которая должна показывать на свою строку, ставится
отдельным предложением или в скобках. Пакет узнать о хвосте не может и потому
только предупреждает.

## Бросок без места: `fail.raise`

Не всякому отказу нужно место. Ошибка программиста, чей текст уходит
оператору в сообщение об аварии или сверяется целиком, от приписки
«файл:строка:» только теряет; чужое исключение, которое пробрасывают дальше,
должно дойти тем же значением. Для таких бросков в `tnt.must.fail` есть
`raise`: он бросает значение как есть, с уровнем 0.

```lua
local fail = require('tnt.must.fail').raise

pcall(fail, 'модель users: поля id нет')
--> false, 'модель users: поля id нет'

local refusal = { code = 'conflict' }
local _, thrown = pcall(fail, refusal)
--> thrown == refusal: объект отказа остаётся тем же объектом
```

`raise` — единственное место в пакете, где бросают без места. Свой
`error(x, 0)` рядом с ним заводить не стоит: `error(x, 0)` и `error(x, -1)`
в Lua одинаково не приписывают места, и различить их проверкой нечем —
один общий помощник проверяется однажды.

### Текст без броска: `must.explain`

Иногда нужен не бросок, а текст: чтобы вернуть отказ парой `nil, err`
или бросить его без места через `raise`. Одиночные проверки отдают текст
сами — их берут прямо из модулей `tnt.must.types`, `tnt.must.range`,
`tnt.must.choice`, — а три проверки по имени собраны поверх реестра
фасада, и их отдаёт `must.explain`: `kind`, `array_of` и `options`
возвращают текст отказа либо `nil` и ничего не бросают.

```lua
local explain = require('tnt.must').explain
local fail = require('tnt.must.fail').raise

local complaint = explain.options({ buid = 1 }, 'приложение', { build = '?', name = '?' })
--> приложение: ключа «buid» нет, есть build, name

if complaint ~= nil then
    fail(complaint)
end
```

Текст тот же, что бросил бы фасад, только без места впереди. Через `kind`
видна любая проверка реестра: `explain.kind(42, 'вес', 'between', 1, 10)` →
«вес — число от 1 до 10, а не 42».

## Чем пришлось поступиться

Здесь то, что выстрелит через полгода.

**Отказ первый, а не все сразу.** `all.string` останавливается на первом
неправильном элементе и о втором не говорит. Собирать все ошибки списком —
задача проверки данных, которые показывают человеку; здесь чинят код,
и чинить его всё равно придётся по одной.

**`raise` последней строкой функции разбор типов концом не считает.**
`emmylua_check` знает, что поток обрывает `error`, а `---@return never`
у функции — нет, ни у своей, ни у чужой: бросок `raise` в конце функции
с объявленным возвратом даёт `missing-return`, а `return raise(…)` —
`return-type-mismatch`. Поэтому отказ ставится условием, а функция
кончается своим возвратом:

```lua
if not self:ok() then
    fail.raise(message)
end

return self
```

**Обёртка вокруг проверки — только с уровнем.** Без него вина на строке
с проверкой, и помощник `local function need_string(v, n) must.string(v, n)
end` покажет на строку внутри себя. Помощнику нужен `must.at(2)`, а глубже
одного помощника лучше не заворачивать: каждый слой — плюс единица к уровню,
и посчитать их через полгода будет некому.

**`number` отвергает NaN, а бесконечность — нет.** NaN ложен в любом
сравнении и потому проскочил бы любую границу молча; бесконечность —
осмысленное «без предела», и отвергать её было бы придиркой. `integer`
отвергает обе: `math.floor(math.huge)` — это `math.huge`, и без явного
отказа бесконечность сошла бы за целое.

**`integer` — про число Lua, `uint64` и `int64` — про целое.** `1LL`,
счётчики `box`, `tonumber64` — всё это тип `cdata`, а не `number`, и
`must.integer(1LL, …)` откажет. Приводить их молча значит однажды потерять
точность там, где её никто не искал: `tonumber` зовёт тот, кто знает, чем
платит. Целое любой записи проверяет `uint64` либо `int64`, и они
возвращают значение как пришло, не приводя: cdata останется cdata.

**Число за 2^53 для `uint64` и `int64` — отказ.** Это порог точности
double: `2^53 + 1` в нём не записать, и число, прошедшее проверку, могло бы
оказаться не тем, которое записали. Такой счётчик приходит из box cdata,
и cdata проверка берёт любого размера.

**`optional` пропускает `box.NULL`.** Он равен `nil`, и `optional.uuid(box.NULL)`
проходит, как проходит `nil`. Обязательному аргументу `box.NULL` не годится
и назван по имени: «идентификатор — UUID, а не box.NULL».

**Объединяются только типы.** `'number|string'` — да, `'number|between'` —
отказ: у проверки с аргументами ожидание зависит от аргументов, и подписи для
объединения у неё нет. `positive`, `not_empty` и `one_of` в объединение
тоже не входят — их пишут второй строкой.

**`instance_of` — не наследование.** Сравнивается одно поле `__type`
метатаблицы, и ничего больше: ни цепочка `__index`, ни родство таблиц.
Объект под `__metatable` имени типа не имеет.

**`options` не подставляет умолчаний и не режет лишнего.** Незнакомый
ключ — отказ, а не молчаливое удаление: настройка с опечаткой в имени
иначе не применилась бы, и никто бы об этом не узнал. Умолчания — дело
вызывающего. Отказ первый, как везде: о втором неправильном ключе `options`
не скажет.

**`length` считает знаки, а не байты.** «Узел» — это четыре знака и восемь
байтов, и предел в байтах обрезал бы кириллицу вдвое раньше, чем ждёт тот,
кто написал «не длиннее 64». У строки с битыми байтами знаков не сосчитать —
такая меряется байтами.

**`matches` берёт шаблон Lua, а не регулярное выражение**: `%d+`, а не `\d+`.
Регулярных выражений в Tarantool нет, а тащить их ради одной проверки значило
бы завести пакету зависимость, которой у него нет. И образец ищется где
угодно в строке, как в `string.find`: привязка пишется явно — `'^[%w-]+$'`.

**`not_empty` не снимает пробелы.** « » — это не пусто. Делать вид, что
пусто, значит спорить с тем, что человек набрал; обрезать пробелы — дело
вызывающего, и делать это надо до проверки.

**`one_of` сравнивает по `==`.** Ни приведения (`'1'` — не `1`), ни сравнения
таблиц по содержимому: две одинаковые таблицы — разные значения, и в списке
допустимых им делать нечего.

**`optional` — про `nil`, а не про «ложь».** `false` — это значение, и
`optional.string(false, …)` откажет.

**Проверка списка стоит времени.** `array`, `array_of` и `all.*` проходят
список целиком: это O(n) на каждый вызов. Для аргументов — имён узлов,
адресов, форм слова — это ничто, а вот в горячем цикле по миллиону кортежей
проверять список на каждом обороте не стоит: проверка аргументов ставится
на границе, а не внутри.

**Аргументы самой проверки проверяются, но не осмысливаются.** Забытая граница,
забытый образец, перечень, которому дали одно значение вместо списка,
и неизвестный тип в `array_of` названы отдельно — и названы так, чтобы было
видно, что чинить строку с проверкой, а не данные:

```lua
must.between(weight, 'вес', 1)        --> верхняя граница для «вес» — число, а не nil
must.matches(name, 'имя узла')        --> образец для «имя узла» — строка, а не nil
must.one_of(level, 'уровень', 'info') --> перечень для «уровень» — массив, а не строка
must.length(name, 'имя')              --> имя: у проверки длины нет ни одной границы
must.options(opts, 'настройки')       --> описание для «настройки» — таблица, а не nil
must.options(opts, 'настройки', { tag = 'strng' })
                                      --> настройки.tag: проверки «strng» нет, есть string, …
```

А вот смысла в них пакет не ищет: `must.between(5, 'вес', 10, 1)`
с перевёрнутыми границами честно отказывает всегда, и сказать об этом
некому. Дальше этого проверять проверку значит писать её второй раз.

**Составных проверок нет.** Ни `positive_integer`, ни `non_empty_array`:
они пишутся двумя строками подряд и читаются лучше, чем имя, в котором
склеены три условия.

## Проверки

Внешней службы у пакета нет, поэтому нет и живых проверок: проверять нечего,
кроме самих сообщений. Тесты лежат в `test/`, по файлу на модуль, и
сравнивают отказы с текстом целиком и дословно — текст отказа и есть то,
ради чего пакет написан.

```sh
.rocks/bin/luatest test/
```

Покрытие строк — 100 %, убитых мутантов — 100 %.
